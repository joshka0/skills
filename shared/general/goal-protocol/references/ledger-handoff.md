# Ledger and handoff

Read only for an existing goal's status, returned dispatch evidence, verification, compacting, or continuation handoff.

Use `GOAL_LEDGER.md` as the coordination index, not a replacement for its goal, dossier, orchestration, ticket, or report artifacts. Keep a compact current snapshot, artifact index, phase gates, traceability index, status board, and open questions; append decisions, assumptions, risks, validations, handoffs, and material ledger entries without deleting history.

Use `D###`, `A###`, `R###`, `V###`, `H###`, and parent trace IDs consistently. Correct an earlier record with a superseding entry. The supervisor owns integrated ledger updates unless that responsibility is explicitly delegated.

For each returned dispatch packet, record its parent IDs, report location, accepted or rejected state, completed evidence, verification result, blocker, and resulting gate or wave transition. Do not treat a return as integration or phase completion until that evidence satisfies the approved packet.

A continuation handoff names the goal root, read-first artifacts, current phase and decision, approved or returned packets, allowed scope, done criteria, escalation triggers, latest validation, and required ledger update. Compact output reports only the current goal, metric, milestone, risk, next action, open question, and latest decision.
