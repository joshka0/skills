# Ledger and handoff

Read only for an existing goal's status, verification, compacting, `/goal` execution status, or a continuation handoff.

Use `GOAL_LEDGER.md` as the coordination index, not a replacement for its goal, dossier, orchestration, ticket, or report artifacts. Keep a compact current snapshot, artifact index, phase gates, traceability index, status board, and open questions; append decisions, assumptions, risks, validations, handoffs, and material ledger entries without deleting history.

Use `D###`, `A###`, `R###`, `V###`, `H###`, and parent trace IDs consistently. Correct an earlier record with a superseding entry. The supervisor owns integrated ledger updates unless that responsibility is explicitly delegated.

For Codex `/goal`, use a goal only when objective verification and stop conditions can be stated. Consult installed CLI help for current command behavior; record material status in the ledger so a later agent does not need session memory.

A handoff must name the goal root, read-first artifacts, current phase and decision, assigned work, allowed scope, done criteria, escalation triggers, latest validation, and required ledger update. Compact output reports only the current goal, metric, milestone, risk, next action, open question, and latest decision.
