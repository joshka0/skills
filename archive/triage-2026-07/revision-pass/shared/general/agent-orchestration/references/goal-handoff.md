# Goal Handoff

Use this compatibility mode when a request uses legacy `codex-goal` language but needs a durable autonomous lifecycle.

Check that the candidate has an objectively verifiable outcome, bounded scope, known evidence, explicit stop conditions, and no unresolved product choice, secret handling, risky production action, or unapproved architecture change. If those conditions are weak, return the missing decision or evidence instead of manufacturing a goal.

Hand the prepared objective to `goal-protocol`, which owns `GOAL_LEDGER.md`, phase artifacts, human gates, and current goal-command behavior. This mode may prepare a concise dispatch-ready handoff; it does not create a durable goal file, prescribe CLI flags, or operate a goal loop.
