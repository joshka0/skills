# Store Metadata

Read this only for the `metadata` mode.

1. Compare store title, description, assets, release notes, links, localization, and paid-feature disclosure with the submitted build and enabled server behavior.
2. Require claims, screenshots, previews, and icons to show real current capability without personal data, secrets, unavailable features, or misleading free/paid implications.
3. Check privacy, support, deletion, and policy links as publicly reachable release evidence rather than placeholders.
4. Keep AI, health, finance, security, accessibility, and subscription claims scoped to what the product can substantiate.
5. Review localized copy and assets for the same disclosure and audience boundaries as the primary listing.

Use current store asset/copy policy for dimensions and field rules. A polished listing does not compensate for a false claim or missing release evidence.
