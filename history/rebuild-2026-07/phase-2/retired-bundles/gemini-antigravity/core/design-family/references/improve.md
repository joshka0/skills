# Improve

Use this mode for one named improvement outcome: system alignment, polish, resilience, performance, adaptation, onboarding, copy, extraction, bolder/quieter direction, color, distillation, delight, or motion.

1. Name one outcome and the user friction it resolves; do not stack unrelated tuning passes.
2. Find the cause before changing the surface: missing token, inconsistent pattern, unsuitable context, absent state, overloaded choice, or unnecessary decoration.
3. Preserve the existing design language while correcting it. Use semantic tokens and patterns; extract a component or token only when more than one real context needs the same contract.
4. Keep core functionality available across context and input methods. Cover realistic long, localized, empty, loading, error, permission, and recovery states when relevant.
5. Measure before and after for performance work. For expressive tuning, adjust hierarchy, density, color, and motion together while preserving one dominant action.
