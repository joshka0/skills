# Project context

Read this only when the user asks to capture durable project context for future sessions.

Inspect the repository first. Capture only decisions that survive a session: domain vocabulary, stable architecture boundaries, chosen toolchain conventions, and documented operating rules. Ask the minimum questions needed for facts the repository cannot establish.

Use the repository's existing AI-instruction or context-file convention. Create a narrowly scoped section or update the matching section without overwriting unrelated instructions. Do not write credentials, executable commands, raw shell output, host-specific values, or transient debugging notes. If no local convention exists, propose a portable schema and obtain the user's location decision before writing.
