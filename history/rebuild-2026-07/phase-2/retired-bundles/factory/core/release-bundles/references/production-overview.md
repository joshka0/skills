# Production Overview

Read this only for the `production-overview` mode.

1. State the submitted artifact/version and whether the assessment covers Apple, Android, or both.
2. Produce one verdict per platform: ready, not ready, needs manual verification, or unknown.
3. Separate store-blocking issues from launch-quality risks and operational gaps; show the highest-risk blockers first.
4. Cover only applicable domains: binary, test/rollout, metadata, privacy/safety, commerce, accessibility/rating, submission access, and automation state.
5. Give every blocker an evidence source, concrete fix, owner, and verification; do not replace missing evidence with a generic checklist.

Do not promise store approval. A clean overview means no known blocker from current evidence, not a guaranteed review outcome.
