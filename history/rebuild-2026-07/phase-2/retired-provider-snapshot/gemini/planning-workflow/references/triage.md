# Issue triage

Read only when an incoming issue needs a configured classification, state recommendation, or public tracker outcome.

1. Read the full issue, prior comments, configured labels, reporter updates, relevant domain/ADR context, and matching out-of-scope records. Do not re-ask resolved questions.
2. Assign one configured category and one configured state role; flag conflicting states for the maintainer instead of guessing a transition.
3. Recommend with evidence, then wait for direction before public mutation. Attempt a bug reproduction before requesting broad clarification.
4. Use an agent brief only after the issue is ready; route a maintainer-approved rejected enhancement to `out-of-scope`.
5. Preview public text unless supplied by the maintainer. Every AI-generated triage comment starts with:

> *This was generated by AI during triage.*

Configured tracker documentation, not this skill, supplies current CLI/API syntax.
