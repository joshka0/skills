# Working in this repository

- Edit skills in `skills/` and provider imports in `native/`. `providers/` is
  generated by `bin/link` and gitignored. Change exposure in `manifest.json`.
- `jsm` installs proprietary skills straight into `providers/claude`, `codex`,
  and `gemini`. List each one in the `jsm` group of `manifest.json`. Never copy
  them into `skills/` or `native/`. Keep `jsm auto-update` at `install_new=false`.
  Never touch consumer-owned `.system` entries.
- `home/` files are live user config (installed by symlink; see `README.md`).
  Change them only when asked.
- Preserve unrelated and uncommitted work. Never rewrite Git history. Prefer
  `/usr/bin/trash` for removal.
- Use repo-relative paths, `$HOME`, or tool home variables. Never commit
  credentials, private keys, or secret-bearing URLs.

## Skill format

- A skill holds only what changes a capable agent's decisions: private CLI
  contracts and quirks, house conventions, and concrete safety boundaries. Cut
  general advice a strong model already follows.
- `description`: one capability plus its trigger, 200 characters or less, and
  distinct from neighboring skills.
- Body: terse facts, commands, and "never" rules. No `Output`,
  `Stop conditions`, or routing-table boilerplate. Use a `references/` file
  only for a large, rarely needed mode.
- State each fact once, in its owner skill, and link to it from elsewhere.
- Before you retire content, check its callers and move any real fact to its
  owner.

## Checks

- `bin/validate-skill.sh <skill-dir>` for each changed skill.
- `bin/link` after an exposure change, then inspect the installed roots.
- For large rewrites, diff the backticked identifiers in the old and new
  versions to catch lost facts.
