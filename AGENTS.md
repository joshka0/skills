# Working in this repository

- Edit skill content in `skills/` or provider-specific imports in `native/`.
  `providers/` is generated by `bin/link`; change exposure in `manifest.json`.
  Keep consumer-owned `.system` entries untouched.
- Preserve unrelated edits and recoverable originals. Remove content within
  the task's scope; prefer `/usr/bin/trash` for local cleanup when practical.
  Do not discard uncommitted work or rewrite Git history.
- Use repository-relative paths, `$HOME`, or tool home variables. Never put
  credentials, private keys, or secret-bearing URLs in this repository.
- `home/` files are live user configuration. Change them or home symlink roots
  only when requested. See `README.md` for installed paths.

## Authoring skills

Use `skill-creator` when available. Keep only guidance that changes a capable
agent's decisions: private tool contracts, chosen conventions, reliable helpers,
and concrete safety boundaries.

Descriptions should identify one capability and distinguish it from nearby
skills. Keep the entrypoint short; link conditional details where they apply.
Do not require a router, fixed mode count, arbitrary word budget, or acceptance
report for an ordinary edit. Preserve the user's scope and existing authority.

Before retiring content, inspect its callers and move any useful instruction to
its actual owner. Keep prior versions in Git or Trash. Preserve import attribution.

Run `bin/validate-skill.sh <skill-directory>` for changed packages. Check routing
and reference selection when they change; exercise changed helpers with meaningful
checks. For exposure changes, run `bin/link` and inspect the installed result.
Report the change, relevant verification, and any remaining limitation.
