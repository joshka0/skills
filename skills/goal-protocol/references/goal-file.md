# Goal file

Create or update `GOAL.md` at the requested root or the repository's goal
location. Include the outcome, relevant facts, allowed scope, acceptance
criteria, verification method, and complete exit condition.

Record unresolved decisions and what work can proceed without them. Preserve
actual approval, side-effect, time, and resource boundaries; do not invent
blanket stops for every schema, dependency, or architecture change.

If starting a runtime goal is requested, verify the installed tool's current
syntax and capabilities. Writing a goal file alone does not start a runtime loop.
