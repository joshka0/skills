# Issue triage

Read the issue, updates, relevant source, configured labels, and prior decisions.
Try to reproduce a reported bug when practical. Do not re-ask resolved questions.

Recommend a configured classification and state with evidence. Apply tracker
changes only within the user's authorization. If implementation is requested
after triage, prepare an AFK brief when useful rather than adding a mandatory gate.

For an authorized durable rejection, record the concept and rationale in the
repository's decision location. Temporary capacity deferrals are not permanent
rejections. Surface a prior rejection for reconsideration rather than silently
closing a new request.

Use the repository's public-comment disclosure policy. Never imply that an
agent's recommendation is a maintainer decision.
