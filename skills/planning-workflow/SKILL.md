# Planning workflow

Produce the requested artifact using current repository and tracker conventions.
Read only the relevant guidance:

| Artifact | Read |
| --- | --- |
| PRD | [prd](references/prd.md) |
| Reviewed implementation plan | [reviewed-plan](references/reviewed-plan.md) |
| Issue slices or AFK brief | [issues](references/issues.md) |
| Triage recommendation or authorized tracker action | [triage](references/triage.md) |

Use `goal-protocol` for a requested durable goal lifecycle and
`agent-orchestration` for live dispatch.

Keep scope, outcome, acceptance criteria, non-goals, and unresolved decisions
clear. Ask only about a decision that materially changes the artifact or
authorized action; continue independent drafting while it is unresolved.

Use configured labels and state mappings. If they are missing, prepare the
artifact locally and identify what is needed for publication. Do not require
new repository configuration merely to write a plan.

Publish or change tracker state only within the user's authorization.
Prepare exact content before any required approval; do not re-ask for authority
already supplied. Report the artifact and any external action actually taken.
