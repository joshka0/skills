# Review

Use this mode for an existing production surface. Treat `UI audit` as evidence-led quality inspection and `UI critique` as evidence-led product and visual judgment.

1. Inspect the actual surface, user task, real content, and interaction states before forming a verdict.
2. For an audit, check semantic controls, labels, keyboard focus/order, non-color status cues, responsive behavior, token consistency, and measured performance or motion risk against current tools and standards.
3. For a critique, assess hierarchy, information architecture, affordance, brand fit, emotional tone, empty/loading/error/success states, and whether the primary action is obvious.
4. Prioritize actionable findings, each with location, user impact, evidence, and a concrete direction. Preserve positive patterns worth repeating; do not invent a finding quota.
5. Keep review-only work read-only. Apply improvements when the task authorizes them.
