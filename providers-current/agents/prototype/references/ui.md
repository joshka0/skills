# UI prototype

Read this only when the question is visual or interaction design.

Build several structurally different variations, normally on the existing route, selected by a stable query parameter and an obvious temporary switcher. Reuse real read-only data/context where it improves judgment, but do not wire real mutations. Variations must differ in hierarchy, layout, or primary affordance, not merely color or copy.

Keep the switcher visibly temporary and outside production behavior. Once a direction wins, capture why, fold the winner into the intended implementation, and remove losing variations and the switcher.
