# Submission And Automation

Read this only for the `submission-automation` mode.

1. Make the reviewer path reproducible: account/demo mode, roles, access to paid or gated features, seeded data, external services/hardware, special configuration, and current support/policy links.
2. Use a concise factual packet or walkthrough when a reviewer cannot naturally reproduce a core, safety, data, or paid flow.
3. Complete only current required release forms and record which facts are API-verifiable, portal-manual, or human/legal judgment.
4. Plan automation in stages: read-only evidence first, then dry-run/staging where available, then an explicit approval checkpoint before mutation or submission.
5. Record release identity, target platform, track/channel, rollout intent, evidence location, manual owner, and rollback/response plan.

Never use automation to bypass a readiness blocker. Discover installed CLI/portal behavior live and provide a manual fallback when automation cannot verify or safely perform a step.
