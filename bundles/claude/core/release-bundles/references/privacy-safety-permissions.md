# Privacy, Safety, And Permissions

Read this only for the `privacy-safety-permissions` mode.

1. Build a data map from app code, native configuration, SDKs, backend, AI systems, payments, analytics, and support tools: collection, sharing, purpose, retention, deletion, and user control.
2. Reconcile the data map with store declarations, privacy policy, in-app disclosure, consent, deletion paths, and the actual submitted artifact.
3. Require each sensitive permission or background capability to have a current user-facing purpose, least-privilege scope, just-in-time disclosure where needed, and a narrower alternative considered.
4. For AI or UGC, verify report/flag, block, moderation, safety escalation, minor protection, and clear high-stakes limitation paths when applicable.
5. Treat declarations, consent, and safety controls as product behavior: evidence must show the user flow, not only a policy document.

Escalate unexplained third-party sharing, broad permissions, missing deletion/control, or unowned safety reports before a release verdict.
